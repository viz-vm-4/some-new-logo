# Art-director review — 05-algorithmic

**Score:** 8/10

**Verdict:** A rigorous, ownable system: three grounds, one serif, a FIG. 0 caption whose numbers really do come from the run (I checked the Kogge–Stone sum of 269 and 321 additions, the 11 uses of "Scratch" and the Himmelblau minima). The shelf clearly reads as one family. It is held back by an accent that disappears in greyscale, a few captions that break the direction's own honesty rule, glyph fallbacks, and two or three plates that turn to mush at 180px.

**Strongest:** mathematical-foundations-for-ml. Gradient descent from 1,472 starts on Himmelblau's function gives a flow field with four red sinks. It reads at 180px, it is correct (the minima sit where (3,2), (−2.81,3.13), (−3.78,−3.28) and (3.58,−1.85) should, with the saddle valley joining the right pair) and the caption states the exact function. The wrap's back cover prints the code that drew the front, which is the whole direction in one object. It is a close call with 5d-parallelism: that plate's 1F1B staircase, first-stage bubble and last-finishing all-reduce are technically right and read instantly as a silhouette.

**Weakest:** build-llms-from-scratch. The arc diagram of BPE token reuse is a cloud of 0.7px carbon arcs at 50–78% opacity on red. At 180px it becomes a muddy ellipse with a thin baseline. The white "Scratch" arcs, which are the answer, are small bumps lost in the mass, and tokenisation is only the first chapter of what the title promises. It is the one core-six cover whose plate neither reads nor explains itself.

## Must fix

1. **system (all 14 renders)** — Every raster render has one row too many: JPGs are 720×889 and PNGs are 1440×1778. The bottom row (two rows at 2×) is page background #DCDBD5, so each cover carries a light hairline along its bottom edge in the library grid. It is most visible on the Carbon and Signal covers. The PDFs are correct at 540×666pt.
   - *Fix:* Re-run `node tools/render.js covers/05-algorithmic/index.html --pdf`. render.js was updated after these renders (21:37 vs 21:36) and now snaps each cover to whole pixels. Confirm every output is 720×888 / 1440×1776. Also give the .sec headers integer heights so the covers never land on a fractional y.
2. **kernel-engineering, 5d-parallelism, sciml, neural-networks-from-scratch, decision-trees-from-scratch** — The accent fails in greyscale. #EF4031 and #D8372B both convert to about 45% grey. On Carbon that is darker than the #ECEAE3 ink texture, and on Paper it is lighter than the black ink. In a greyscale conversion the Kernel dependency path, the 5D all-reduce blocks and the SciML shock Y all but vanish. The NN boundary merges with its contours. The decision-tree root split reads lighter than its children, which inverts the caption's 'heavier the earlier it is asked'. NOTES claims a greyscale check, but the one idea the accent carries (it marks the answer) does not survive it.
   - *Fix:* Give the accent a channel that is not colour. Draw each accent path twice: first a ground-coloured casing stroke 2–3px wider, then the accent on top. Keep accent strokes at 2.4px or more; Kernel is 1.5px and the Reasoning dashes are 0.8px. Knock back the non-answer texture where it competes: Kernel diagonals from 0.9 to about 0.45 opacity, 5D forward/backward to about 0.7, SciML particles from 0.8 to about 0.55. The answer is then the highest-contrast element in luminance as well as hue. Re-check with a real greyscale conversion of the JPGs.
3. **ai-context-engineering, mathematical-foundations-for-ml, sciml, kernel-engineering, decision-trees-from-scratch, git-github-masterclass, charlie-sound-room** — Glyph-level font fallback. The Google Fonts build of IBM Plex Mono has no Greek and none of these symbols, so the PDFs embed DejaVuSansMono for λ and ◎ (context), η (maths), π ₜ ₓ (SciML), ᵏ (kernel '2ᵏ'), ≤ (trees), ○ (git) and → (sound). In a type system whose signature is the mono caption, these glyphs are visibly heavier and wider at 10px. They will also change on any other machine's print pipeline. Separately, the git caption breaks the command 'git log / --graph' across two lines.
   - *Fix:* Either add a deliberate second mono that has these glyphs, e.g. `family=Noto+Sans+Mono&text=λ◎ηπₜₓᵏ≤○→` placed second in --mono, or rewrite the glyphs in a code voice ('lr = 0.0006', 'lambda = 0.55', 'u_t + u·u_x', '2^k', 'depth <= 7', '->'). Wrap `git log --graph` in `white-space:nowrap`. Re-check `strings *.pdf | grep FontName` until DejaVu is gone.
4. **sciml** — The caption calls this 'the classic benchmark for physics-informed networks', but the generator does not run it. It uses u₀ = −sin πx + a₃ sin 3πx + a₅ sin 5πx (seeded, |a₃| 0.3–0.5) up to t = 1.5. The classic benchmark (u₀ = −sin πx, t in [0,1]) forms a single stationary shock at x = 0 around t ≈ 1/π. The red Y of two shocks merging, which is the plate's image, cannot happen in it, and a SciML reader will see that at once. This breaks the direction's own 'caption says exactly what ran' rule.
   - *Fix:* Put the real initial condition in the caption: 'Burgers' equation … from a perturbed start, u₀ = −sin πx + 0.4 sin 3πx − 0.2 sin 5πx, to t = 1.5', using the seeded values, and drop 'the classic benchmark'. Alternatively, run the true benchmark and accept a single-stem plate.
5. **charlie-reasoning-room** — The caption reads 'The best arm (p = 0.72) … it won 1,345 of the 1,600 pulls'. The code's pre[T] counts how often the arm was chosen, not how often it paid out. It also contradicts itself: 84% 'wins' from an arm with a 72% payout.
   - *Fix:* Change the wording to 'it was pulled 1,345 times of the 1,600'. If you want a win count too, count the rewards separately.
6. **pi-vs-hermes-vs-codex** — Panels 'I · DROP OLDEST / II · ROLLING SUMMARY / III · TIERED MEMORY' sit directly under 'Pi vs Hermes vs Codex' in the same order, so they read as Pi = drop-oldest, Hermes = rolling summary, Codex = tiered memory. As far as I know none of the three simply drops the oldest turns; Pi and Codex both summarise on compaction. NOTES says the mapping is deliberately not claimed, but the layout claims it.
   - *Fix:* Best option: take the actual policy of each agent from the book and label the panels truthfully ('Pi — …'). If that isn't possible, break the implied mapping. Letter the panels A/B/C, order them so they don't mirror the title, and add to the caption: 'three textbook policies, not the agents' own implementations'.
7. **charlie-vision-room** — The caption says a Vision Transformer 'tells them apart by position embeddings. These are its fixed 2-D sine–cosine ones'. The original ViT learns 1-D position embeddings. Fixed 2-D sin–cos is the MAE / Simple-ViT choice, so the caption overstates.
   - *Fix:* Change it to '…by position embeddings — here the fixed 2-D sine–cosine kind used by MAE and Simple ViT (d = 256): …'.

## Improvements (highest impact first)

1. **build-llms-from-scratch** — Rethink the plate and keep the in-page BPE. Draw the merge tree of the book's own title: the 47 characters of 'Build Large Language Models (LLMs) from Scratch' on a baseline, and every merge that touches them as an arch over the span it joins. Arch height is merge order, strokes are 1.2px carbon, and the arches that build 'Scratch' are white at 2.4px. The result is a full-width skyline of nested arches that reads at 180px and literally shows a tokenizer building the title. A heavier alternative in the same spirit as the NN cover: train a one-head causal attention layer on the library's titles and draw its lower-triangular attention matrix. A triangle silhouette reads as 'LLM' instantly.
2. **charlie-language-room** — The 0.9px beam-search tree sits in the left 70% of the room (x 135–465 of 132–588). It disappears at 180px, and the stray labels 'Vis' and 'Rearning' read as bugs rather than wit. Keep the model and redraw the tree. Either root it at the room's centre and fan it radially to fill the square, or make it a top-down tree across the full 456px width. Scale stroke width with beam probability (1–4px) so the likely paths form a visible trunk. Keep the red path to 'Language Room' at 2.4px or more, and label only finished whole-word titles.
3. **pi-vs-hermes-vs-codex** — Panel I (drop-oldest, 146 compactions) is a solid grey mass of 0.5px lines at 0.78 opacity, right at the print floor. Beside the clean fans of II and III it looks like a render glitch, and it dominates the thumbnail. Give all three panels the same line budget: draw every third message trajectory, or end evicted lines cleanly at the left edge of the window instead of overdrawing. Raise the raw strokes to 0.65–0.7px so none are screened hairlines.
4. **system** — The plates' edges and column are inconsistent. Charted plates run x 36–684 (decision-trees frame, ai-context window bar, pi panels, 5D, git, kernel, LLM baseline), while the meta line, title, caption and imprint sit on 40–680. The 4px overhang is visible at full size, e.g. the trees frame against the caption below it. Only maths and NN bleed off the trim. Make it a written rule and apply it everywhere: fields (maths, NN, SciML) bleed left and right, and charts (trees, git, 5D, pi, kernel, context) sit exactly on the 40px column, x 40–680. The decision-trees plate also draws all 300 points as identical open circles, so its 'three classes' can't be seen; use ●/○/× to match the three leaf shadings.
5. **system (titles)** — Maths: 'Mathematical Foundations<br>for Machine Learning' does not fit at 62px, so the browser auto-wraps it into a short-short-long rag. Hand-set it as 'Mathematical / Foundations for / Machine Learning'. 5D: line 1 ends on 'for', and at 60px it is the smallest title in the set, with about 125px of dead band above the plate. Set '5D Parallelism / for Large / Model Training' at about 74px; it still ends before y 290. SciML: set 'Scientific / Machine Learning / (SciML)' at 70px so 'Machine Learning' stays together. Then do the optical kerning pass NOTES promises on the 84px settings.
6. **system (scaling)** — Before writing 38 more generators, map all 52 slugs to a generator in one table to catch collisions early. Charlie II already uses ViT position embeddings, which 'Build a ViT from Scratch', DeiT and 'Transformers for Vision & Multimodal' will all want. The three Kimi K3 books should be a sub-series like Charlie, e.g. one MoE-routing run seen at three scales. The survey books ('… Fundamentals', '… Mastery', 'Foundations for AI & ML') have no single algorithm; give them a rule too, such as a plate computed from the book's own capsule list or topic graph. Add one thumbnail rule to the spec: every plate carries a single accent figure of 2px or more that survives at 180px and in greyscale.
