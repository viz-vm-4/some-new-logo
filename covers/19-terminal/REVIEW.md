# Art-director review — 19-terminal

**Score:** 8/10

**Verdict:** This is a coherent, well-executed system with real conviction: one typeface, one grid, three inks, level shown by the prompt glyph and the cursor as the imprint mark. Every title reads at 180px and everything prints as clean vector, but because the direction claims to be literal machine output, a few captions and diagrams that are technically wrong have to be fixed before it can ship.

**Strongest:** mathematical-foundations-for-ml: the histogram is built from the 420 samples themselves, each value printed in its own bin. The bars are sorted so each column reads -0.25 up to -0.00, and the n·Δ·pdf curve is traced in Selection blue. At 180px it reads instantly as a bell curve, it survives greyscale, and up close every glyph is true. It is the clearest proof of the stdout idea. neural-networks-from-scratch (a 7 made of its own bytes, beside its softmax) and charlie-sound-room (a waveform whose centre row spells the transcript) come close.

**Weakest:** decision-trees-from-scratch: at 180px the field is a wall of grey monospace cut by a blue bar and a black cross. No tree and no data are visible. The three class tones (.26/.50/.74) sit too close together to separate the regions, and the depth-3 split at 4.85 divides two regions with the same tone (both virginica), so the partition looks arbitrary. The title break "Build Decision / Trees from Scratch" also splits the subject noun.

## Must fix

1. **kernel-engineering** — The GEMM tile shapes don't match. A[M,K] is drawn with 2 tile-columns (mat(rA,0,6,2,…)) but B[K,N] has 3 tile-rows (mat(2,cB,3,5,…)), so the inner dimension K is 2 on A and 3 on B. Your own code comment says 'K tiles = 3 here'. Readers of a kernel book will spot this straight away.
   - *Fix:* Make K the same on both matrices. The least disruptive option is K=2: draw B as mat(2,cB,2,5,…), which is 2 tile-rows (rows 2–10), and move the A/C block up (rA≈14) so the gap stays even. Keep the blue k=0 tiles as they are. Alternatively, draw A with 3 tile-columns and shift cB right to 52 with 4 tile-columns for B and C.
2. **5d-parallelism** — The caption code would raise a TypeError. In PyTorch, init_device_mesh(device_type, mesh_shape, *, mesh_dim_names=None) takes the axis names as a keyword-only argument, but the caption passes ("dp","pp","tp","cp","ep") positionally. The direction's whole claim is 'what the book's code prints', so the code has to run.
   - *Fix:* Change the caption to: mesh = init_device_mesh("cuda", (2, 2, 2, 2, 2), mesh_dim_names=("dp", "pp", "tp", "cp", "ep")). That is about 98 characters and still fits the caption row, which starts at col 6.
3. **charlie-sound-room** — The numbers contradict each other. The chips say USER 0.0–2.4 s and AGENT 2.6–4.9 s, which is a 200 ms gap, but the gap label and the caption both say 240 ms.
   - *Fix:* Either relabel the chips 'USER 0.00–2.36 s' and 'AGENT 2.60–4.90 s', or change both the gap label and the caption comment to 200 ms. While you are there, give space characters at least one column in turn(), so the centre line reads 'move my' rather than 'moveemy'.
4. **pi-vs-hermes-vs-codex** — The emblem misrepresents the book's subject. It shows compaction as deleting stop-words, then vowels, then truncating words to 5 characters. No production agent compacts context that way: compaction is a model-written summary of older turns, with the recent turns kept word for word. The three funnels also use different profiles (linear, 1.7 power, 0.62 power) in the same left-to-right order as 'Pi vs Hermes vs Codex', so readers will map a behaviour onto each named agent. That contradicts the NOTES' claim that nothing is attributed to any agent.
   - *Fix:* Keep the three funnels and the blue MEMORY blocks, but give all three the same profile. Replace the vowel stripping with the real mechanism. The top of each column shows the transcript turns in full. A dashed '── limit ──' row marks the trigger. Below it the column narrows into a short summary in plain words (for example 'lexer bytes→str fixed · input streamed, 38 MB · split-token test added · committed'), ending in MEMORY. The silhouette stays and the content becomes true.
5. **charlie-reasoning-room** — Text breaks the 24px safe margin while every other element on the grid sits at col 6 (36px). The line 'reward = 1 if answer == 408 else 0 · advantage = …' starts 13px from the left trim. The outer leaf chips '340 + 68' start 18px from the left trim and '240 + 148' ends 12px from the right trim. charlie-sound-room has the same problem: the 'USER 0.0–2.4 s' chip sits 12px from the left trim.
   - *Fix:* Set in-field text labels at col 6 (x=36), in line with the caption, prompt and imprint. For the reasoning tree, use X=[16,45,74,103] with leaf offsets of ±6 columns instead of ±7. The outer chips then fall at cols 5–114, inside 24px, and the tree stays centred on the root at col 60. Move the sound-room USER chip from col 2 to col 6.
6. **mathematical-foundations-for-ml** — The caption doesn't match the picture, and one axis label is clipped. hist(x, bins=20) spans min(x) to max(x), so it would not give the 0.25-wide bins over [-2.5, 2.5] that are drawn, and the '# * marks 420 · 0.25 · pdf(x)' comment would then be wrong. Separately, the last tick label '+2.5' starts at col 119, so only a lone '+' shows at the right trim.
   - *Fix:* Change the caption to x = randn(420); hist(x, bins=20, range=(-2.5, 2.5)). Then either right-align the final tick label so it ends at col 119, or label only -2.0 to +2.0 and let both end ticks bleed unlabelled.

## Improvements (highest impact first)

1. **system** — The cursor is the Vizuara mark, but it changes size by a factor of 2.5 across the shelf. It is 25×37px after 50px titles, 30×44 after 60px titles, 15×22 after the 30px subtitles (all four Charlie covers and pi-vs-hermes-vs-codex), and a 12×18 hollow outline on kernel-engineering. That outline is a speck at 180px, so the 'coming soon' state can't be seen. Fix the mark at one size (the 50px-title block, 25×37) and one position rule: after the last title line, on the title baseline. Set subtitles below as plain output with no cursor. Draw the hollow version at the same 25×37 with a 4px stroke so it survives the thumbnail.
2. **system** — Fix these title line breaks. All of them fit the 50px, 5-cell setting inside the 24px margin. decision-trees-from-scratch: 'Build Decision Trees / from Scratch', which keeps the subject together and matches 'Neural Networks / from Scratch'. 5d-parallelism: '5D Parallelism for / Large Model Training', which drops the lone 'Training' line and keeps the compound whole (the line ends at about 658px, and the cursor at about 692). All four Charlie covers: 'Charlie and / the Language Room' etc., so no line ends on a dangling 'the'. mathematical-foundations-for-ml, optionally: 'Mathematical / Foundations / for Machine Learning'.
3. **decision-trees-from-scratch** — Rethink the emblem inside the same partition. Plot the 150 real iris samples as class letters (s / v / g) at their (petal_length, petal_width) cells, set at full weight. Push the region textures far apart: setosa at .16, versicolor at .50, virginica at .86 in reverse video. The clusters then show why each split is where it is, the handful of points misclassified at the 4.95 boundary become the story, and at 180px it reads as data separated by lines rather than a textured cross. Keep the root split in blue. Another option that is pure stdout is sklearn's export_text() output, with its '|---' indentation forming the tree.
4. **charlie-vision-room** — At full size the eye breaks into scattered black chunks, and the byte values run backwards. Bytes are printed as ink, so the pupil reads f7 and the white of the eye 05, whereas real image data stores the pupil near 00 and the sclera near f0. Encode luminance (dark means a low byte) and keep ink proportional to 255 minus the byte. Make the pupil a solid disc distinct from the ring of the iris. Make each gutter one whole blank row and column so the 13×9 patch grid reads as a grid. Use the bottom 3 rows for the step that makes this a ViT: a token strip '[CLS] p0 p1 … p116' with the selected patch's token in blue, showing the patch becoming a token.
5. **system** — Plan how this scales to 50 covers. The emblems that work (7, bell curve, attention triangle, roofline, waveform, tree of chains) each have one silhouette that reads at 48px. The ones that don't (decision trees, and to a degree ai-context-engineering and 5d-parallelism) are uniform fields of text. The remaining catalogue is heavy on LLM, agent and RAG books, which will pull towards more 'boxes of transcript' like ai-context and pi. Make it a rule that every emblem passes a 48px silhouette test and that no more than about 40% of the field is even texture. Keep a registry of silhouette types (triangle, bell, ramp, glyph, waveform, tree, lattice, funnel, window) so that books on neighbouring subjects never share one.
6. **neural-networks-from-scratch** — The selected '7', which is the answer and the most important datum on the cover, is set as a single 6px blue cell with no padding, so it reads as a sliver. It is the least legible label in the softmax panel. Set it as a 3-cell chip ' 7 ' in Selection, or keep the 7 bold carbon like the other digits and let the bar and 0.874 carry the blue. Separately, raise the top rows of the pi-vs-hermes-vs-codex funnels from tone .26 (a 40% tint at 7.5pt, weight 360) to at least .50. That is the transcript's most readable text, and at 40% it will break up in 4-colour print.
