# Art-director review — 07-riso

**Score:** 7.5/10

**Verdict:** Overprint is a disciplined system with real conviction. The chrome holds on all 15 covers, the key-ink level coding works at 180px, and in the best emblems the overprint really does carry the idea. Before it ships it needs to fix one font fallback, two smoke/title collisions, a few greyscale and legibility failures in small labels, and three emblems that misstate their subject (DeiT's arrow, the RL path against its own policy, the invented Pi/Hermes/Codex ranking).

**Strongest:** build-llms-from-scratch: the sentence 'Every token attends to itself and those before it' is set as the row tokens down the causal-mask staircase. The caption and the diagram are the same object, so it is true to the mechanism, uses only two inks, and reads clearly as a staircase at 180px. kernel-engineering is a close second, because the pink/yellow overprint literally is the output tile C[i,j].

**Weakest:** charlie-vision-room: the 'eye' does not read as an eye. The almond is quantised into 33px patches, and then the arch clips its corners. The iris (t=0.9) and skin (t=0.5) screens print at almost the same dot size, so the result looks like a pixel-art face or a space invader with two blue 'pupils'. It also leaves out the actual ViT idea (the image turned into a token sequence), and it repeats the aqua patch grid already used on deit-from-scratch.

## Must fix

1. **mathematical-foundations-for-ml** — Font fallback. The PDF embeds LiberationSerif-Italic, and its ToUnicode map holds only 'μσ'. Instrument Serif has no Greek, so every μ and σ in the axis labels (μ−2σ … μ+2σ, src/books.js line 148) falls back to a system font, while '2', '+' and '−' stay in Instrument Serif. The labels mix two faces, and the fallback will differ from machine to machine (Times on a Mac).
   - *Fix:* Set the maths labels in a Google font that has Greek italics, e.g. STIX Two Text Italic or Noto Serif Italic, for the whole label so the faces don't mix. Alternatively, outline μ/σ as SVG paths. Re-render and confirm the PDF embeds only Bricolage, Instrument Serif, DM Mono and the chosen maths face.
2. **charlie-language-room / charlie-reasoning-room** — The chimney smoke collides with the title. The puffs are fixed (src/books.js line 308, halftone box from y=60 at x≥560) regardless of title width, so the middle Sunflower puff overprints the right stem of the 'm' in 'Room' on both covers. On Reasoning Room the top puff also touches the 'm'. Vision and Sound only escape because their titles are shorter.
   - *Fix:* Make the smoke respond to the title. Clip the puff halftone box to x > title.right + 16 or y > title.bottom + 12, or move the puff path so it drifts right and off the page below the title's baseline. Then re-check all four Charlie covers.
3. **pi-vs-hermes-vs-codex** — The 'MEMORY' labels are paper colour (#F4F0E6) knocked onto the blocks (line 282). On the Yellow Pi block the contrast is about 1.1:1, so the label is nearly invisible at full size. In greyscale all three labels disappear, because Yellow goes to about 212 against paper at 240.
   - *Fix:* Print 'MEMORY' in the key ink (black), which overprints cleanly on all three flash blocks. If you want to keep the knockout, put it on a key-black band at the foot of each block. Size 14px and up.
4. **pi-vs-hermes-vs-codex** — The top slug reads '9 CAPSULES · 1 HRS'. The plural is hard-coded (src/riso.js line 206).
   - *Fix:* Pluralise: hours === 1 ? 'HR' : 'HRS', and the same for capsules. Every future 1-hour book depends on this.
5. **pi-vs-hermes-vs-codex** — The emblem makes an unsupported comparative claim about three real products. Each column gets different parameters (line 263: PI c0 0.2/e 1.5, HERMES 0.36/1.0, CODEX 0.5/0.7), so Pi appears to compact earliest into the biggest memory block (about 68px) and Codex latest into the smallest (about 41px). It reads as a benchmark result the notes admit it is not. Separately, the speaker marks alternate ■ and ●, which are the system's own level glyphs (intermediate and beginner), printed on an advanced cover.
   - *Fix:* Give all three columns identical c0/e so the cover makes no ranking, or derive the differences from what the book actually documents. Replace the speaker marks with glyphs outside the level vocabulary, e.g. ▲/▼ or 'U'/'A' in DM Mono.
6. **deit-from-scratch** — Technical error. The arrow runs from the CNN teacher into the 'dist' token (lines 502–504), and the notes say it is 'fed by a convolutional teacher'. In DeiT the distillation token is a learned embedding prepended to the patch sequence. The teacher never produces or feeds it: the teacher's prediction is the target for the dist token's output head.
   - *Fix:* Reverse the logic. Draw a dashed key-ink connector from the dist token's output to a small teacher-label target beside the CNN stack, labelled 'target' or 'distill loss', with no arrowhead pointing into the token. Keep cls and dist attached to the front of the patch sequence.
7. **reinforcement-learning** — The agent's path contradicts the greedy policy drawn beneath it. The path turns up at column 3 (row 4) and runs up through rows 3 and 2, but all three of those cells carry ▶ arrows, half-buried under the path stroke. The moves are ties in distance, but the viewer sees the agent ignoring the policy the cover says it follows.
   - *Fix:* Break ties in favour of the drawn path, so those three cells show ▲. Alternatively, route the path along the arrows. In cells the path crosses, drop the arrow or print it knocked out of the path so arrow and path never overlap.
8. **machine-learning-fundamentals** — The 'p = 0.5' label is 13px DM Mono, rotated −32° and sitting directly on the two-ink halftone (line 545). It is scrambled at full size and will vanish in print. Also, Bubble Gum (about 175) and Cornflower (about 154) go to almost the same grey, and both classes use identical outlined circles, so the two-class idea flattens in greyscale.
   - *Fix:* Set the label at 15–16px on a small paper-knockout pill, or move it to where the boundary exits onto clean paper at the right edge. Give the classes different key-ink markers (○ for one class, × for the other) so the split survives greyscale.
9. **5d-parallelism** — The legend fails in greyscale: TENSOR (Aqua), PIPELINE (Pink) and CONTEXT (Aqua+Pink) become three near-identical mid-grey bars, so three of the five axes can't be told apart. The Aqua glow halftone (box to y=bot+40=810, line 223) also runs behind the legend labels at baseline 812.
   - *Fix:* Separate the axes by form as well as ink, e.g. TENSOR as a solid bar, PIPELINE with a key-ink dotted core, CONTEXT as a double rule, and match the legend swatches. End the glow box at y≈785 so the legend sits on clean paper like the rest of the foot.

## Improvements (highest impact first)

1. **system** — The grid of halftone squares is becoming the default emblem: 5 of 15 covers use it (LLM mask, DeiT patches, Vision Room patches, RL gridworld, Kernel C tiles). The unwritten catalogue includes ViT, CNN, CV Bootcamp, Transformers ×2, NanoVLM, DSA and Kimi, so at 50 books the shelf will read as graph paper. Before drawing the other 35, lay them out on a form matrix (cell grid, graph/tree, curve/field, stack/line screen, geometry) and cap cell grids at roughly 1 in 6. Pick the other forms on purpose for the vision books.
2. **charlie-vision-room** — Rebuild the emblem around what a ViT actually does. Inside the door, show a simple high-contrast image that reads at 180px (e.g. a crescent moon or a bold 'C' for Charlie) cut into a 4×4 grid of large patches with at least 3 clearly different tones. Along the factory floor, show the same 16 patches laid out as a single row of tokens, led by a solid key-ink [CLS] token. The image turning into a sentence is the idea, and it no longer duplicates DeiT's 8×8 grid.
3. **sql-masterclass** — The join-as-Venn picture is the well-known misleading metaphor, since an INNER JOIN matches rows on a key rather than intersecting two sets, and here it looks like a generic Venn logo. Keep the 'overprint is the query' rule but make it true. Show CUSTOMERS (id, name) in Aqua and ORDERS (id, customer_id) in Yellow as two small ruled tables, offset so only rows with matching keys overprint to green. One customer with two orders appears twice in the green result, and unmatched rows stay single-ink. Label 'INNER JOIN … ON customers.id = orders.customer_id'.
4. **charlie-language-room** — The pink token pills look like a generic redacted-paragraph or chat icon and say little about 'Inference Engineering'. Show speculative decoding with the overprint: a draft model's run of k tokens as pink outlines, verified tokens printed solid (pink over Sunflower), the first rejected token struck through in key ink, and the target model's corrected token after it. The sibling 'inference-engineering' book can then take the KV-cache / paged-attention picture.
5. **system** — Write a rule for where art crosses the title, and loosen the tracking. On ai-context-engineering the window's top edge slices 'Engineering' at about 45% of the x-height, which looks accidental. On mathematical-foundations-for-ml the curve's green outline cuts through the counters of 'e' and 'a' in 'Learning'. Snap such overlaps to the baseline so only descenders dip in, or drop the key-ink outline where it crosses type. At wdth ≤86 (DeiT, RL, LLMs) the −0.018em tracking nearly closes pairs like 'nf', 'rc' and 'Tr'. Riso ink spread on uncoated stock will fill those gaps, so use about −0.008em at the narrow widths.
6. **system** — Protect the level coding and the imprint across inks. (1) On Vision/Sound, the Federal Blue band, door frame and numeral overprint the Sunflower and print as olive #3D3C09, barely different from the black-over-Sunflower on Language/Reasoning. Knock the Sunflower out under key-ink linework so the level ink prints true. (2) The V press-mark's flash arm almost disappears in Yellow/Sunflower (Math, Pi, Kernel, RL) and in greyscale. Across the shelf it also cycles through orange, aqua and pink, which are the retired pinwheel hues, on the brand mark itself. Give the V a fixed second ink or a key-ink screen. (3) Read level, capsules and hours from books.json instead of hard-coding them in src/books.js, so 50 covers can't drift from the catalogue.
